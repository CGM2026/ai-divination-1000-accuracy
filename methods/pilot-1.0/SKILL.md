# 三张扑克牌占卜

版本：1.0。适合用户问某件生活事件会怎样发展、能否在期限内发生，以及行动选择的发展倾向。先读 [牌义](../post-test-skill/references/symbols.md)。这是从360轮符号探索整理的解释方法；预测能力仍待检验。

## 实际使用

1. 保留用户给出的背景、问题与时间范围。缺失时间若影响回答则简短询问；开放问题可以给趋势，但需要核验的预测应写明期限与发生标准。不要把已经发生的结果当未知未来。
2. 将背景与问题保存为 JSON，字段 background、question，可加 deadline、yes_definition。执行 `python scripts/draw.py --input 输入.json --output 抽牌记录.json`。脚本从52张无大小王牌中无放回抽三张，保留顺序；同一输出文件重试只返回原牌。同一问题的新抽牌须是用户主动要求的新一轮，不能因牌不好解释而重抽。
3. 先列出事实允许的发展路径，再用三张牌选择关注的关系。每张牌以“花色所看的对象 × 牌值所看的尺度或职能”阅读，再检查同花、同值及顺序。顺序是解释的展开路线，默认没有过去/现在/未来的固定牌位。
4. 给出一个最倾向的未来结果，说明最可能的过程、转折或限制；以“我倾向于……”表述。明确区分题面事实、牌面联想和预测。不能只复述背景或给建议，也不能用两个相反结局包揽命中。
5. 二元问题记录 prediction=0或1 与 p_yes（0到1，0.5及以上判1）。概率是主观把握，不是经过校准的成功率。强事实或算术不被牌推翻；证据不足时仍可给低把握的方向，写清最不确定的一环。建议另列一句，不能暗中把“如果你采取建议”当成原预测的前提。

## 回答格式

**抽到：** 三张牌（按程序顺序）。

**回应：** 先用一到两句直接回答问题，再用一小段说清倾向的发展。避免每句话都留后路。

**牌面怎样连起来：** 三张牌分别落在哪个已知对象或待验证关系上，组合如何改变关注点。5—9缺少独立依据时如实说明本次主要按花色或组合读，不硬编词典。

**把握与核验：** 低/中/高把握；二元评估时保留 p_yes、期限、一个明确判定标准。未校准的数值不必在日常正文展示，评估记录必须保存。

可选一句行动建议；与预测结果分开。

## 模拟评估

预测者只读取公开背景、已冻结技能、自己的抽牌与当前允许的开发反馈。不得打开隐藏结局、评分文件、作者笔记或留出集反馈。每例记录 id、version、cards、prediction、p_yes、answer、rationale、uncertainty。先保存预测再评分；留出集预测全部提交后才能揭晓结果。已提交记录不可因看到结局改写。
